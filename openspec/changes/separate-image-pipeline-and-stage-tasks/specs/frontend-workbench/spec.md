## ADDED Requirements

### Requirement: 工作台必须区分完整图片处理和独立阶段任务
图片库与处理任务工作区 MUST 将完整图片处理 Job、独立阶段任务和未归类历史诊断项呈现为不同的工作项。完整 Job MUST 作为可展开的父项展示视觉向量、Agent 语境和文本 embedding 三个阶段及其状态、诊断和叶子 Task 链接；独立阶段 Task MUST 作为无父 Job 的单项任务展示；未归类历史诊断项 MUST 只展示其历史状态和诊断，且不得被标记为独立阶段任务。界面不得只根据 Task 类型、创建时间或状态推断任务归属。

#### Scenario: 查看完整图片处理 Job
- **WHEN** 用户在处理任务工作区打开一个图片处理 Job
- **THEN** 界面显示该 Job 的总体状态并可展开查看三个阶段的状态与对应叶子任务

#### Scenario: 查看独立阶段任务
- **WHEN** 用户在处理任务工作区查看一个手动发起的独立 Agent 或 embedding Task
- **THEN** 界面将其显示为独立任务，而不将其嵌入任意图片处理 Job

#### Scenario: 查看未归类历史任务
- **WHEN** 用户在处理任务工作区查看一个未归类历史图片阶段 Task
- **THEN** 界面将其展示为只读历史诊断项，不提供完整重试或阶段仅重试动作

### Requirement: 工作台必须提供两种明确且受状态约束的重试操作
图片库和处理任务工作区 MUST 分别提供“完整重试”与各阶段“仅重试”操作，并清楚标识其影响范围。完整重试 MUST 提交完整 Job；阶段仅重试 MUST 提交对应的独立阶段任务。活动 Job 或活动独立 Task 的重复操作 MUST 被禁用、复用或呈现为明确的冲突反馈，界面不得暗示已经创建第二个并行执行。界面不得向服务端提交 scope、内部 Job/Task 归属、claim、grant 或 callback 数据。

#### Scenario: 用户选择完整重试
- **WHEN** 用户对图片或失败的图片处理 Job 选择“完整重试”
- **THEN** 界面提交完整 Job 操作，并在返回后展示或轮询该 Job 的阶段状态

#### Scenario: 用户仅重试文本 embedding
- **WHEN** 用户对图片选择“仅重试文本 embedding”
- **THEN** 界面提交独立文本 embedding Task 并在任务列表中展示它
- **AND** 界面不得把该操作标记为完整 Job 重试或展示未创建的 Agent/视觉子任务

#### Scenario: 阶段操作不可用
- **WHEN** 所选图片阶段已有活动执行、当前图片不存在，或服务返回稳定的 policy/目标错误
- **THEN** 界面显示对应的不可用原因和可恢复操作
- **AND** 界面不得伪造成功、提交隐藏的下游阶段或丢失原任务诊断
