## Why

普通用户任务工作台当前按最近更新时间排序。任务在轮询期间发生进度、状态或错误变化时会反复移动，用户难以追踪创建先后，分页请求之间也可能因为可变排序键产生重复或遗漏。

## What Changes

- 普通用户任务列表改为按创建时间倒序返回，最新创建的任务位于顶部。
- 任务列表分页 cursor 与排序使用同一 `(created_at, id)` 稳定键，状态和进度更新不再改变既有任务的相对位置。
- 图片处理父 Job 与普通任务在工作台中统一按各自创建时间混排。
- 工作台列表列名和行时间改为“创建时间”；任务状态、进度和轮询行为保持不变。
- 兼容内存任务服务、公开任务列表测试和文档契约同步更新。
- 管理员任务列表、Worker 的 FIFO 调度顺序和任务详情接口不在本次范围内。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `task-status`: 普通用户任务列表改为按创建时间和任务 ID 倒序稳定分页。
- `frontend-workbench`: 普通用户任务工作台按创建时间稳定展示任务与图片处理 Job，并显示创建时间。

## Impact

影响公共核心的任务 PostgreSQL repository、兼容内存任务服务、图片处理 Job 列表、普通用户任务工作台及其测试和 OpenSpec delta。任务数据模型无需迁移，管理员控制面不变。本变更须先在开源仓库提交并经审核，之后才能按精确 commit 同步到 Server。
