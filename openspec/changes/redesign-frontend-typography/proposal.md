## Why

当前前端已经覆盖检索、图片库、上传和异步任务，但桌面与移动端的文字层级、触达尺寸和信息分组偏小偏密，导致状态、错误和任务进度不易扫描。现在需要在不改变既有 API 与工作流语义的前提下，建立更易读、可响应、可访问的工作台视觉与交互规范。

## What Changes

- 重构前端工作台的视觉层级，采用简洁且有一点性格的 MemeMeow 工作台语言：保留轻微倾斜的品牌标记、固定紫蓝主题色，并让图片内容成为主要视觉对象。
- 提高正文、标题、按钮和导航的字号与最小触达尺寸，重新平衡行高、间距和内容密度，避免单纯放大造成溢出。
- 优化四个工作区（检索、图片库、上传、处理任务）的信息架构和空态、加载、禁用、错误、成功状态，使关键动作和恢复路径可扫描。
- 保留现有四路由工作区、API 契约、缓存生成动作和任务轮询行为；移动端继续提供四项导航，但提升触达区域并确保稳定布局。
- 增强键盘焦点、对比度、响应式断点、`prefers-reduced-motion` 和窄屏溢出处理，并补充稳定的前端行为/可视验证。
- 更新前端设计文档，记录新的颜色、字体层级、组件状态和响应式规则。
- 保留现有页面标题和功能文案；不新增营销式标题、装饰性小字、eyebrow、随机图案或拟造图片字幕。
- 侧栏与主导航不得重复提供同一上传主动作；上传入口只在主导航保留，避免桌面端出现两个“上传图片”入口。
- 概念草图 v2 仅用于 OpenSpec 规划与视觉评审，不替代 v1，也不改变正式前端代码。
- 将“最近看过”记录为后续独立能力，本次不在页面或效果图中展示。

## Impact

- 主要影响 `frontend/src/App.vue`、`frontend/src/style.css`、相关前端测试与截图验证。
- 可能更新 `DESIGN.md` 及必要的前端文档；不新增运行时依赖。
- 不修改 `frontend/src/api.js` 的 API 语义，不改变后端接口、任务状态机或文件安全边界。
- 实现阶段需保留工作区中已有的用户/并行代理改动，并在其基础上兼容现有缓存动作等行为。
