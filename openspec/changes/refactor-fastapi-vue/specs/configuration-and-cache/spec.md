## Purpose

集中管理服务运行配置和检索缓存生命周期，保护模型密钥不离开后端，并让用户明确知道何时可以搜索以及何时需要重新生成缓存。

## ADDED Requirements

### Requirement: 模型配置必须来自服务端环境
系统 MUST 从服务端 `.env` 或等价的进程环境读取嵌入模型和 VLM 的 API Key、Base URL、模型标识及路径配置。前端请求不得修改或持久化这些秘密值。

#### Scenario: 启动时读取配置
- **WHEN** 服务启动且环境变量存在
- **THEN** 系统加载配置并使用对应模型服务

#### Scenario: 必需配置缺失
- **WHEN** 执行依赖某模型的操作但对应配置缺失
- **THEN** 系统返回明确的配置缺失错误，不输出密钥内容

### Requirement: 配置查询必须脱敏
系统 MAY 提供运行状态查询，但响应 MUST 只包含模型名称、Base URL 和密钥是否已配置等非秘密信息，绝不得返回完整 API Key。

#### Scenario: 查询配置状态
- **WHEN** 客户端请求配置状态
- **THEN** 响应中的密钥字段仅表示已配置/未配置或脱敏尾缀

### Requirement: 缓存生成必须可观察且互斥
系统 MUST 能够触发检索缓存生成，并通过任务状态报告其进度和结果。同一时间存在缓存生成任务时，新的生成请求 MUST 返回已有任务或明确的冲突，不得并发写入同一缓存。

#### Scenario: 首次生成缓存
- **WHEN** 缓存不存在且客户端触发生成
- **THEN** 系统创建缓存生成任务，任务成功后搜索可用

#### Scenario: 已有缓存时刷新
- **WHEN** 缓存已存在且客户端明确触发刷新
- **THEN** 系统异步生成新缓存；生成期间默认继续使用旧缓存，直到新缓存完整替换

#### Scenario: 重复触发生成
- **WHEN** 已有缓存生成任务处于 `queued` 或 `running`
- **THEN** 系统不创建第二个并发生成任务，并返回已有任务标识或 `409`
