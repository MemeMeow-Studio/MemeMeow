## Purpose

为 MemeMeow 的浏览器工作台提供可读、可扫描且适配桌面与移动设备的交互规范，让用户能够快速检索、整理、上传图片并判断异步任务状态，同时保持既有后端行为不变。

## ADDED Requirements

### Requirement: 工作台必须提供清晰且稳定的四区导航

工作台 MUST 在桌面和移动视口提供检索、图片库、上传、处理任务四个可识别入口；上传入口只在主导航保留，侧栏或其他区域 MUST NOT 重复提供同一“上传图片”主动作；当前入口 MUST 有明显选中状态，导航文本和触达区域 MUST 在移动设备上可读且不因内容换行导致布局跳动。

#### Scenario: 桌面切换工作区
- **WHEN** 用户通过桌面导航选择任一工作区
- **THEN** 页面显示对应工作区内容，当前导航项保持选中状态，其他工作区内容不会覆盖当前主要操作区

#### Scenario: 移动端使用导航
- **WHEN** 用户在窄屏设备点击四项导航中的任一项
- **THEN** 入口保持至少 44px 的可操作尺寸，标签完整可读，工作区切换后页面不出现水平滚动

#### Scenario: 桌面上传入口不重复
- **WHEN** 用户查看桌面工作台导航
- **THEN** “上传图片”只出现于主导航，侧栏底部不再出现重复的上传主动作

### Requirement: 主要内容必须使用可读的字号层级

工作台 MUST 对正文、工作区标题、按钮/输入控件和功能元数据采用有明显差异的字号与行高层级；正文和关键操作在常规桌面与移动视口均不得小于 16px，文件类型、时间和状态等必要功能元数据不得小于 14px，并 MUST 保持可辨识的对比度。界面不得用 10-12px 的装饰性小字、eyebrow 或拟造图片字幕替代内容层级。

#### Scenario: 检索工作区阅读与提交
- **WHEN** 用户打开检索工作区并输入自然语言查询
- **THEN** 输入提示、查询文本和提交动作在不放大页面的情况下清晰可读，提交控件的文字与状态不会被截断

#### Scenario: 任务信息扫描
- **WHEN** 用户查看处理任务列表或详情
- **THEN** 任务类型、状态、进度、消息和错误恢复信息按层级分组显示，长文件名或时间信息不会挤压状态文本或造成水平溢出

#### Scenario: 保留现有页面文案
- **WHEN** 用户打开任一既有工作区
- **THEN** 页面保留该工作区已有的标题和功能文案，不展示新造的营销式标题、装饰性短句或与图片无关的拟造字幕

### Requirement: 工作区必须覆盖关键异步和空内容状态

检索、图片库、上传和处理任务 MUST 分别提供可理解的空态、加载态、禁用态、错误态和成功反馈；错误反馈 MUST 说明问题并给出可执行的恢复动作，禁止仅展示原始枚举或无上下文的错误码。

#### Scenario: 缓存未就绪时检索
- **WHEN** 用户提交查询且检索缓存尚未就绪
- **THEN** 检索动作显示明确的不可用原因和缓存生成/重试入口，且不伪造为空结果

#### Scenario: 批量上传部分失败
- **WHEN** 一次上传中有成功文件和失败文件
- **THEN** 界面分别展示每个文件的结果、失败原因和下一步动作，成功文件仍可进入图片库

#### Scenario: 没有图片或任务
- **WHEN** 图片库或处理任务没有可展示条目
- **THEN** 界面说明当前为空的原因，并把首个可行操作放在用户无需滚动即可找到的位置

### Requirement: 前端交互必须满足基础可访问性和响应式约束

所有可交互控件 MUST 支持键盘焦点和可见焦点样式，文字与背景 MUST 满足普通文本至少 4.5:1 的对比度，用户启用 `prefers-reduced-motion` 时 MUST 禁止非必要过渡；在 320px 及以上宽度下 MUST 无水平溢出。

#### Scenario: 键盘操作工作台
- **WHEN** 用户只使用键盘浏览导航、输入框、按钮和任务详情入口
- **THEN** 焦点顺序与视觉顺序一致，焦点指示清晰，所有主要动作均可触发

#### Scenario: 减少动态效果
- **WHEN** 浏览器开启 `prefers-reduced-motion: reduce`
- **THEN** 工作台保留内容和状态反馈，但移除非必要的进入、悬停和加载动画
