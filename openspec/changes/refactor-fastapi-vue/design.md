
## Context

当前入口由 `app.py` 启动 Streamlit，页面直接调用 `services/` 中的搜索、VLM 和文件操作；`api.py` 已提供一部分 FastAPI 接口，但没有覆盖图片管理和标注工作流，且搜索文档与实现的请求方式不一致。现有数据以本地文件和缓存为主，没有数据库，也没有可靠的任务状态存储。

本设计遵循变更规格中的单机部署、服务端 `.env`、内存任务状态和资源包功能移除约束。规格正文见同一 change 下的 `specs/` 目录。

## Goals / Non-Goals

**Goals:**

- 让 FastAPI 成为唯一业务入口，Vue 只通过 HTTP API 和受控媒体 URL 访问数据。
- 复用现有搜索、嵌入、VLM 和文件处理能力，先分离边界，再逐步替换 Streamlit 页面。
- 用统一 DTO、错误格式和任务状态管理器支撑同步与异步操作。
- 保证本地文件访问经过根目录校验，且密钥只存在服务端环境。
- 使新旧部署能够在迁移阶段可验证、可回滚。

**Non-Goals:**

- 本期不实现资源包导入、启停、社区同步或资源包导出。
- 本期不实现 Web 用户、角色、注册、登录、JWT 或多租户隔离。
- 本期不引入数据库、Celery、消息队列、WebSocket 或云对象存储。
- 本期不重写嵌入模型、VLM 提示词和核心相似度算法。

## Decisions

### 1. 保留现有服务层，新增 API 边界

将搜索和标注逻辑整理为可注入的服务对象，由 FastAPI lifespan 初始化一次，并通过依赖注入提供给路由。路由层只负责请求校验、权限策略、任务提交和响应映射；文件路径解析、VLM 调用和缓存处理留在服务层。

选择复用而不是立即重写，是为了先锁定行为并减少模型结果、缓存格式和文件命名规则的同时变化。替代方案是按 Vue 页面逐一改写 Python 逻辑，风险是 UI 迁移和业务重写无法区分回归原因。

### 2. 采用单一规范检索入口

保留路径 `POST /search` 作为唯一检索入口，请求和响应由一个共享 schema 定义。前端与外部客户端均调用该入口；不再维护 GET 别名或重复的 `/api/search`。图片结果统一映射到受控媒体 URL，路径格式转换只存在于响应映射层。

这样可以消除 README、Streamlit 和现有 API 的三套约定。替代方案是同时维护 v1/v2 或 GET/POST 兼容层，但会引入重复 schema 和长期漂移。

### 3. 使用受控文件标识，不传绝对路径

客户端只提交图片目录标识、文件标识和文件名。后端将标识解析到配置的图片根目录，使用规范化路径检查、扩展名检查和符号链接边界检查后才执行读取、写入或重命名。媒体接口复用同一解析器。

这将浏览器的路径问题收敛为一个安全边界。替代方案是直接暴露静态目录或接受客户端路径，虽然代码少，但无法满足目录越界和信息泄露约束。

### 4. 长任务使用进程内任务管理器

缓存生成和批量 VLM 操作通过统一任务管理器提交，任务记录包含 `task_id`、类型、状态、进度、消息、时间戳和错误。执行器使用受控的后台线程；状态查询为 `GET /tasks/{task_id}`。同类不可并发的任务使用任务类型锁，避免同时写同一缓存。

服务关闭时将非终态任务标记为失败；启动后不恢复旧任务。该方案满足当前单机需求且不增加 Redis/Celery/数据库。代价是进程崩溃会丢失任务详情和未完成进度，后续若需要可靠恢复再单独引入持久化队列。

### 5. `.env` 是唯一秘密配置来源

服务启动时读取 `.env` 或进程环境，至少覆盖嵌入模型、VLM 的 API Key 和 Base URL，以及本地数据根目录。仓库只提供 `.env.example`。配置状态接口只返回脱敏信息，前端没有密钥输入和写配置操作。

选择环境配置是因为当前部署是单实例且没有用户权限模型；继续让页面写共享 YAML 会把服务端秘密暴露给任何能使用页面的人。替代方案是数据库配置或前端临时密钥，均会增加持久化或泄露面。

### 6. Vue 采用页面级迁移，后端先行

先实现并测试搜索、图片库、上传、标注和任务 API，再以 Vue 3 单页应用替换对应 Streamlit 页面。前端通过轮询任务状态更新进度，图片列表和媒体预览使用 API 返回的标识和 URL。每迁移一个工作流，执行其契约测试和手工验收，再删除对应 Streamlit 入口。

选择页面级迁移可以保留可工作的旧界面作为短期回滚点；替代方案是一次性删除 Streamlit 并同时发布前后端，失败时无法定位是 API 还是 UI 问题。

## Risks / Trade-offs

- [现有服务层依赖 Streamlit 工具或全局状态] → 先抽取路径、配置和进度报告接口；在服务层契约测试通过前不删除 Streamlit 依赖。
- [任务线程在进程崩溃时丢失] → 在 API 和文档中明确内存任务语义；任务副作用采用逐文件提交，避免伪造全量成功。
- [移除资源包后旧缓存仍含资源包字段] → 缓存加载时显式拒绝或迁移旧格式，并在迁移任务中清理资源包路径依赖。
- [远程图片结果无法通过本地媒体接口访问] → 检索服务在返回前完成按需下载；下载失败的候选不进入响应。
- [API 契约变化导致外部客户端失效] → 先发布 OpenAPI 和迁移说明，契约测试固定 `POST /search` 的 schema、状态码和媒体 URL 语义。
- [VLM 调用耗时和费用不可控] → 批量操作必须是长任务，限制并发和重试次数，并逐文件报告失败。

## Migration Plan

1. 建立 `.env.example`、FastAPI 应用生命周期和统一错误/schema 基础；不改变现有 Streamlit 启动方式。
2. 实现搜索、配置、缓存和任务 API，补充契约测试，确认 `POST /search` 和媒体 URL 行为。
3. 实现图片库、上传和标注 API，完成路径安全与逐文件结果测试。
4. 创建 Vue 应用，按搜索、图片库、上传、标注顺序迁移页面；每步保留 Streamlit 回滚入口。
5. 停止 Streamlit 生产入口，删除资源包相关路由和页面代码；保留历史数据前先执行缓存兼容检查。

回滚时恢复 Streamlit 入口和原 API 进程即可；`.env`、图片文件和旧缓存不应被迁移步骤删除。新 API 与旧 Streamlit 可在过渡期间共享同一图片目录，但不得同时写入同一份缓存。
