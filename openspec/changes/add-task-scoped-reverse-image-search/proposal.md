## Why

当前 Agent 是否能够以图搜图由运行环境是否暴露 SerpApi 密钥隐式决定，前端无法为单次语境生成选择策略，服务端也无法可靠区分缓存复用与实际供应商调用。需要把这项能力收束为任务级显式策略和后端统一接口，以保护供应商密钥、准确记录使用情况，并为未来多用户或更换供应商保留稳定边界。

## What Changes

- 为上传自动生成、单图生成、批量生成和失败重试提供 `forbid` 与 `auto` 两档以图搜图策略；策略由前端随本次请求提交并持久化到任务输入。
- 新增仅供受控 Agent 运行环境访问、当前不要求认证的供应商无关反向图片检索接口；接口按 `task_id` 读取任务策略，禁止客户端自行声明或覆盖策略。
- 将现有 SerpApi Google Lens 脚本改为内部接口的薄 CLI 客户端；Agent 不再获得 SerpApi 密钥，也不再直接管理供应商缓存。
- 后端统一执行参数校验、并发缓存互斥、供应商调用、响应脱敏和稳定错误映射；缓存命中不增加实际供应商调用次数。
- 按 scope、任务、图片和调用请求持久化幂等用量流水，并在任务结果及图片 provenance 中记录策略、是否尝试、是否使用缓存结果、缓存命中数、实际供应商调用数和最终结果。
- 当前内部接口不引入用户认证、任务 token 或角色系统；接口契约保持供应商和认证机制无关，以便未来在接口背后增加认证或替换供应商。

## Capabilities

### New Capabilities

- `task-scoped-reverse-image-search`: 定义任务级 `forbid`/`auto` 策略、Agent 内部检索接口、后端缓存与供应商调用、用量流水以及密钥隔离边界。

### Modified Capabilities

- `image-labeling`: 图片语境生成入口增加本次任务的以图搜图策略选择，并保证所有生成和重试入口一致传递该策略。
- `task-status`: 语境任务状态与结果增加可审计的反向图片检索摘要，且任务去重不得复用策略不一致的活动任务。

## Impact

- 前端：生成策略控件、上传与生成请求序列化、失败任务重试和任务详情展示。
- FastAPI：请求模型、任务 payload、内部反向图片检索接口、稳定错误响应和配置状态。
- Agent 运行器与 Skill：任务 prompt、内部接口地址与任务标识传递、薄客户端脚本、移除 Agent 环境中的 SerpApi 密钥和直接调用说明。
- PostgreSQL：反向图片检索用量流水及相关约束、索引和迁移；任务结果和 Meme provenance 沿用现有 JSONB。
- 缓存与供应商：现有文件缓存逻辑迁入后端服务边界，并保持同键互斥、脱敏和缓存兼容策略。
- 测试与文档：覆盖四类前端入口、API 策略校验、内部接口、并发缓存、调用计数、失败恢复、密钥隔离和结果审计。
