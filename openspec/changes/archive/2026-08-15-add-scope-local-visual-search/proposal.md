## Why

当前 Agent 研究图片时只能依赖自身观察、文字检索和可选的外部反向图片服务，无法利用当前 scope 中已经完成研究的相似 Meme 及其结构化语境。新增本地图像向量能力后，系统可以在图片入库后异步生成视觉向量，并让 Agent 通过数据库匹配复用已有研究结果，同时保持图片、语境和文本索引之间清晰的生命周期边界。

## What Changes

- 图片成功入库后先提交可重试的视觉向量生成任务；该任务成功后幂等提交对应的 Agent 语境任务，上传请求不等待模型推理。
- 在 PostgreSQL/pgvector 中新增与现有文本向量分离的视觉向量持久化和 scope 内精确相似度查询能力。
- 在 `research-meme-context` Skill 中增加薄匹配脚本；脚本只查询已有视觉向量，不加载视觉模型、不触发即时推理，也不调用外部供应商。
- 查询图必须已有当前模型的有效视觉向量；候选图必须属于同一 scope、视觉向量有效，并且当前图片内容已经成功生成 Agent 语境。
- 视觉向量任务、Agent 任务和文本索引任务按单图依赖顺序衔接，但不同图片允许并发处理；失败和显式重试默认只作用于当前阶段。
- 活动模型使用公开可下载的 DINOv2 ViT-B/14（官方模型标识 `dinov2_vitb14`，768 维输出）；视觉模型、权重和预处理由服务端配置并写入向量身份，本变更不允许跨模型向量混查。
- GIF 第一版使用首帧生成视觉向量；后续是否采用多帧聚合由真实检索效果决定。

## Capabilities

### New Capabilities

- `visual-similarity-search`: 定义视觉向量的异步生成、版本化持久化、Agent-ready 候选资格、scope 隔离匹配和 Skill 薄客户端契约。

### Modified Capabilities

- `image-ingestion`: 图片入库成功后必须提交视觉向量任务，并以该任务作为自动语境处理的单图前置步骤。
- `task-status`: 增加视觉向量任务类型、稳定错误和阶段内重试语义，并规定视觉任务成功后幂等提交 Agent 任务。
- `configuration-and-cache`: 增加服务端视觉模型、权重与预处理配置，以及不泄露本地路径或敏感配置的状态查询行为。

## Impact

- PostgreSQL schema 和 Alembic 迁移：激活固定 768 维 DINOv2 ViT-B/14 视觉向量表、保留 DINOv3 H+/16 表供显式回切、模型与图片指纹约束及查询索引。
- FastAPI 和后端服务：新增 scope-bound 视觉匹配接口、视觉任务处理器、上传任务衔接及稳定错误。
- Docker Compose：新增 CPU 视觉向量 Worker 或等价的隔离运行边界，并以只读方式提供图片和模型权重。
- Agent Runtime 与 Skill：挂载并调用新的薄匹配脚本，继续通过任务标识推导 scope，不获得数据库凭据或模型执行能力。
- 依赖与部署：增加 CPU 推理运行时和公开 DINOv2 ViT-B/14 权重；权重不内嵌公开镜像，容器需要按实测内存和延迟配置。
- 文本语义搜索继续使用现有独立索引，本变更不改变 `/search` 的自然语言检索契约。
