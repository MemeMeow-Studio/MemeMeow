## Purpose

为耗时的缓存生成和批量 VLM 操作提供统一、可轮询的任务状态契约，使前端能够展示进度和错误，并明确内存任务在服务重启时的失效语义。

## ADDED Requirements

### Requirement: 系统必须为长任务返回任务标识
耗时操作 MUST 立即返回唯一任务标识和 `202` 状态，不得要求客户端保持原请求连接直到任务结束。短操作可以同步完成。

#### Scenario: 创建长任务
- **WHEN** 客户端提交缓存生成或批量 VLM 操作
- **THEN** 系统返回唯一 `task_id`、初始状态 `queued` 和任务类型

### Requirement: 系统必须提供统一任务状态
任务状态接口 MUST 返回任务类型、状态、进度（无法估计时可为 `null`）、当前消息、创建时间、完成时间和错误信息（如有）。状态只能按 `queued -> running -> succeeded/failed` 转移。

#### Scenario: 查询运行中任务
- **WHEN** 客户端查询存在的运行中任务
- **THEN** 系统返回 `running` 状态及最新可用进度，不重复执行任务

#### Scenario: 查询未知任务
- **WHEN** 客户端查询不存在的 `task_id`
- **THEN** 系统返回 `404`，错误标识为 `task_not_found`

### Requirement: 失败任务必须可诊断且不伪装成功
任务异常时 MUST 进入 `failed` 状态，返回稳定错误标识和面向用户的消息；已完成的部分结果 MUST 按各业务规格保留，不得将失败任务报告为成功。

#### Scenario: 执行过程失败
- **WHEN** 长任务中的外部模型调用或文件处理失败且无法继续
- **THEN** 系统记录失败状态，状态查询返回错误信息，且任务不再执行后续步骤

### Requirement: 服务重启必须使未完成内存任务失败
任务状态暂存于内存。服务启动后，任何此前未完成且无法从内存恢复的任务 MUST 被视为失败；系统不得报告其仍在运行或自动重复执行。

#### Scenario: 服务在任务执行期间重启
- **WHEN** 服务重启且此前任务尚未进入终态
- **THEN** 该任务不可继续轮询为运行中，新的服务实例将其视为失败或返回任务不可恢复错误
