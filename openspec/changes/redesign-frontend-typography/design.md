## Context

现有前端由 `frontend/src/App.vue` 和 `frontend/src/style.css` 组成，四个工作区共享一个 Vue 单体页面，并通过 `frontend/src/api.js` 调用既有接口。图片库缓存动作、任务轮询和后端状态机已经存在；本变更只建立新的工作台呈现层，不能改变这些行为契约。

## Goals / Non-Goals

**Goals:**

- 用“简洁、有一点性格的 MemeMeow 工作台”视觉世界重建工作台的排版、导航、状态和响应式布局。
- 以 16px 正文、32-36px 工作区标题、14-15px 控件文字和至少 44px 触达尺寸为基线，再按实际内容调整密度。
- 让检索、图片库、上传和处理任务的主要动作、状态与恢复路径在首屏可扫描。
- 保留当前 API 调用、缓存生成入口、上传语义和任务轮询；通过测试和桌面/移动截图验证。

**Non-Goals:**

- 不改后端接口、数据模型、文件安全策略或任务状态转换。
- 不引入新的 UI 框架、图标依赖或运行时服务。
- 不把工作台改造成营销落地页，也不添加未经产品事实支持的统计或能力声明。
- 不增加“最近看过”能力；该需求留给后续独立变更。

## Decisions

### 以 token 驱动 CSS，而不是局部覆盖

在 `style.css` 顶部集中定义颜色、字号、行高、间距、边框和焦点 token；组件规则只消费 token。这样可以同时调整桌面与移动层级，并降低当前一次性 CSS 的维护成本。备选方案是逐个元素追加覆盖，短期改动少但容易产生级联冲突和断点不一致。

### 保留桌面侧栏与移动四项导航，改变触达与层级

桌面继续使用侧栏加内容区，移动端保留四个既有入口以避免路由和测试不稳定，但改为固定高度、完整标签、明确选中态和至少 44px 触达区。上传入口只在主导航保留；侧栏底部不得再放置重复的“上传图片”按钮。完全改成汉堡菜单会隐藏工作区，增加一次额外点击且削弱高频操作效率。

### 用语义状态标签替代原始枚举直接展示

前端建立有限的状态到用户文案/视觉角色映射：queued、running、succeeded、failed、cache_not_ready 等状态都由标签和辅助说明呈现，保留原值用于调试或无障碍上下文。未知状态使用安全的通用文案，不让原始 enum 破坏布局。

### 固定主题色和克制品牌标记，而不是装饰性主题

将紫蓝 `#5157D9` 固定为主交互色、深墨 `#2A2638` 固定为品牌与主要文字色、`#F8F7FB` 固定为背景；错误与成功仅在必要状态使用功能色。轻微倾斜的深色方形 `M` 标记是唯一非功能性品牌动作。列表和工作区保持连续布局，避免每个区域套一层圆角卡片，也不加入圆形气泡、随机贴纸、警示纹理、吉祥物或奇怪图案。备选的多色点缀和工业纹理会使视觉注意力偏离图片与操作，故不采用。

### 保留既有文案，用真实内容建立层级

保留现有页面标题和功能文案，不新增“找到那个刚好的反应”一类营销式标题，也不在图片上叠加拟造标题或装饰性短句。正文和关键控件以至少 16px 建立层级；文件类型、时间与状态等功能元数据可使用 14-15px，但不使用 10-12px 的装饰性小字。这样既遵守用户对大字和简洁的要求，也不丢失操作界面所需的信息。

### 以内容约束响应式，而不是仅按设备缩放

为长文件名、任务消息、按钮组和图片缩略图设置可收缩轨道、换行/截断策略和最小宽度；在 320px、移动常用宽度和桌面宽度分别验证。字号增大时同步调整网格、间距和容器宽度，避免只放大字体导致水平溢出。

### 概念草图 v2 的上传入口取舍

概念草图保留桌面侧栏中的四项主导航，并移除侧栏底部重复的“上传图片”按钮；上传主动作只由“上传图片”导航入口承载。移动端沿用同一四项导航，不额外添加底部上传按钮，确保同一动作只有一个稳定位置。

### 验证采用两轮有界截图与行为测试

实现后运行现有单测和构建，补充关键状态/导航断言，并用 Playwright 或项目现有浏览器方式捕获桌面与移动视口。第一轮集中修复布局、对比度、焦点和状态问题，第二轮确认修复没有回归；不扩展为无限微调。

## Risks / Trade-offs

- [Risk] 放大字号会减少单屏任务行数。→ [Mitigation] 只放大正文和关键操作，功能元数据保持至少 14px 的稳定次级层级，并为任务行设计可折叠详情。
- [Risk] 现有并行改动与模板重构发生冲突。→ [Mitigation] 实现前读取工作区 diff，保留缓存动作和 API 行为，不使用破坏性回滚。
- [Risk] 移动端导航标签在极窄屏幕换行。→ [Mitigation] 固定导航轨道和图标/标签布局，验证 320px 宽度并处理长文本。
- [Risk] 状态映射遗漏新 enum。→ [Mitigation] 提供未知状态回退文案，并在测试中覆盖已知状态和未知值。

## Migration Plan

1. 在现有前端代码之上重构 token、布局和状态呈现，保持 API 调用签名不变。
2. 运行前端单测、构建和桌面/移动验收；发现问题时只修改本 change 范围内的前端文件。
3. 部署静态前端资源即可；若视觉回归不可接受，回滚前端静态资源，不需要数据库或后端迁移。

## Open Questions

无。字体、导航形式、视觉世界和 API 兼容边界已在本设计中确定，后续只需按内容实际尺寸校准。
