## Context

当前 Agent 结果先后经过 OpenCode runner、executor 和任务服务，任务状态还会从 SQLite/JSON 历史或 PostgreSQL ORM 重新组装；图片处理 job 又独立维护阶段、错误和恢复 attempt。多个边界各自保留了部分原始映射，因此旧记录、异常消息和 payload 派生字段可能绕过正常结果 schema。实现必须兼容已有任务状态机和图片处理阶段顺序，并保留外部 API 的稳定标识。

## Goals / Non-Goals

**Goals:**

- 在 Agent 结果接收前拒绝未知字段和敏感内容，错误信息不携带原值。
- 集中提供可复用的公开字段投影，用于任务、图片处理和恢复历史的所有 HTTP 出口。
- 对旧的脏 JSON、脏数据库字段和不完整恢复绑定 fail-closed。
- 让各入口在单元测试和 API 测试中可直接验证白名单、拒绝和清理行为。

**Non-Goals:**

- 不改变 scope 授权、任务认领、图片处理状态机或数据库迁移语义。
- 不把公开 DTO 用作内部 worker payload；内部调用仍显式使用原始对象。
- 不尝试 DNS 解析任意域名，也不保证识别所有未知形式的秘密，只覆盖明确的公开安全边界。

## Decisions

### 统一边界模块

在 `backend/public_dto.py` 集中定义 Agent 顶层字段、敏感文本扫描、标识/错误/时间清理和按任务类型结果投影。这样新增 HTTP 出口可以复用同一规则；相比每个 endpoint 自己复制正则，统一实现能避免规则漂移。

### 接收边界整体拒绝

Agent 结果遇到任何未知字段或敏感命中都整体失败，而不是删除字段后继续写入。结果是外部不可信数据，部分接受会让调用方误以为研究结果完整，也会把敏感信息隐藏到未覆盖字段；整体拒绝能保持事务和错误语义清晰。

### 响应边界显式投影

任务结果按 `task_type` 使用固定字段映射，图片阶段、warning 和 error 逐字段构造响应。历史字段不满足类型或格式时省略，非法任务状态收束为 `failed`，恢复能力必须同时具有合法 session、executor attempt 和 selector。相比通用递归删除，这种投影不会因未来内部字段命名变化而意外扩大公开面。

### 多层调用点校验

OpenCode 和 executor 都校验 Agent 结果，任务从磁盘/ORM 读取时再次投影，HTTP 摘要和图片快照最后再构造公开 DTO。重复边界检查增加少量 CPU，但可以覆盖文件、数据库和动态 payload 派生的不同信任边界；异常消息只返回稳定错误码和清理后的短文本。

### 时间和标识收窄

公开时间只接受可解析的 ISO 形式，公开标识只接受受控 opaque 字符集；绝对路径、控制字符、目录分隔符和损坏的恢复标识不会回显。该策略兼容现有 UUID/attempt/session 标识，同时避免把任意历史字符串当成 API 字段。

## Risks / Trade-offs

- [风险] 历史任务结果字段比当前实现丰富，投影后客户端可能看不到旧的附加字段。→ 这是有意的公开契约收窄；先保留任务类型要求的兼容字段，并通过 API 契约测试固定允许集合。
- [风险] 凭据扫描存在未知格式漏检。→ 同时检查 Settings/环境中的登记值及常见 bearer、token、JWT、云凭据和 URL 形式；结果接收仍拒绝未知字段，避免敏感数据藏在扩展结构中。
- [风险] 脏时间或状态被收束后 UI 缺少诊断。→ 保留稳定错误码和 failed/unknown_execution 状态，原始值只留在受保护的内部存储，不进入公开响应。

## Migration Plan

1. 先部署代码和公开投影测试；不修改既有数据库 schema。
2. 读取旧任务或图片 job 时即时清理，不批量重写历史数据，降低迁移风险。
3. 若回滚代码，历史数据仍保持原样，后续版本再次读取时可重新投影；不需要数据回滚。
