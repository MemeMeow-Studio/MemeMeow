## Why

当前项目的核心业务逻辑位于 Python 服务层，但交互入口仍依赖 Streamlit 页面，页面状态、文件操作和业务逻辑相互耦合，导致 API、界面和文档难以保持一致。现在将交互层重构为 Vue、服务层收敛为 FastAPI，并先用可验收的行为规格锁定真正需要保留的功能，降低迁移期间的回归风险。

## What Changes

- 将现有 Streamlit 检索、图片上传和图片标注流程重构为 Vue 前端与 FastAPI 后端协作的单一 Web 应用。
- 建立统一的检索 HTTP 契约，覆盖普通语义检索、可选 LLM 增强、结果数量限制、缓存未就绪和错误处理。
- 将图片目录浏览、上传、创建目录、预览和重命名收敛到后端受控的文件 API，浏览器不直接操作服务器路径。
- 将 VLM 单张标注、自动命名、批量上传标注和失败重试建模为明确的业务行为。
- 将缓存生成和批量 VLM 处理建模为内存中的长任务；服务重启后未完成任务标记为失败，不引入持久化任务队列。
- 将嵌入模型和 VLM 的密钥、地址等配置统一从服务端 `.env` 读取；前端不得读取、修改或回显密钥。
- 保留 API 保护模式和限流，作为服务端访问策略；不迁移 Streamlit 用户登录和多用户权限体系。
- **BREAKING** 移除本期全部资源包功能，包括本地/在线资源包导入、资源包启停、社区资源包组同步和资源包 ZIP 导出；后续另行实现。
- **BREAKING** 以新的统一检索接口取代当前 README 与实现之间不一致的 GET/POST 约定，并同步更新 API 文档。

## Capabilities

### New Capabilities

- `meme-search`: 自然语言语义检索、可选 LLM 增强、结果去重和图片访问结果。
- `image-library`: 本地图片目录的列表、预览、创建和重命名。
- `image-ingestion`: 多图片上传、格式校验、重复文件处理和可选自动命名。
- `image-labeling`: VLM 描述生成、人工编辑文件名、前后图片导航和批量标注行为。
- `task-status`: 长任务提交、内存状态查询、进度报告、失败处理和服务重启语义。
- `configuration-and-cache`: 服务端 `.env` 配置、脱敏配置状态和检索缓存生成/刷新。
- `api-access-policy`: API 白名单保护模式和按客户端限流。
- `public-api-compatibility`: 统一 API 入口、请求/响应格式、错误码和迁移后的兼容边界。

### Modified Capabilities

无。当前 `openspec/specs/` 中没有已建立的能力规格，本变更从零建立迁移基线。

## Impact

- 后端：保留并整理 `services/` 中的搜索、嵌入、VLM 和缓存逻辑；重构 `api.py` 的路由、模型和错误处理；移除 Streamlit 运行入口及其页面依赖。
- 前端：新增 Vue 应用，负责检索、图片管理、图片上传和标注工作流；通过 FastAPI 获取图片，不依赖服务器绝对路径。
- 配置：新增 `.env.example`，运行时读取 `.env`；不再允许 Web 页面写入 API Key 或 Base URL。
- API：新增统一检索、图片和任务接口，保留保护模式与限流；现有不一致的 `/search` 调用方式需要迁移。
- 测试与文档：为规格中的正常、失败、边界和重启场景增加后端契约测试，并同步 API 文档和部署说明。
- 依赖：引入 Vue 前端构建链；后端首期不引入 Celery、消息队列、数据库或新的认证系统。
