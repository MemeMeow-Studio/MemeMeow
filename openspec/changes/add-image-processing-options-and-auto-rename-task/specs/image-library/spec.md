## ADDED Requirements

### Requirement: 完整重试必须由服务端枚举当前 scope 的全部核心未就绪图片
“完整重试所有未就绪” MUST 由服务端在授权的当前 scope 内枚举目标，不得使用客户端当前已加载的图片标识作为完整集合。核心就绪 MUST 同时要求当前图片版本具有有效视觉产物、匹配当前 Agent 配置和本次 `reverse_image_policy` 的有效语境，以及匹配当前 metadata hash 和模型版本的文本 embedding；任一核心条件缺失、失败、被阻止、执行状态未知或过期时，该图片 MUST 被纳入本次目标。前端搜索、状态筛选、排序、分页和已加载数量不得缩小或扩大服务端枚举范围。

#### Scenario: 未就绪图片位于未加载页
- **WHEN** 当前 scope 有未就绪图片不在客户端已加载的第一页中，用户提交“完整重试所有未就绪”
- **THEN** 服务端仍将这些图片纳入处理目标，并返回本次枚举与提交结果摘要

#### Scenario: 前端正使用局部筛选
- **WHEN** 用户在图片库中启用了名称或状态筛选后提交完整重试
- **THEN** 服务端按当前 scope 的全部图片判断核心就绪，不把前端可见集合当作目标集合

#### Scenario: 仅自动重命名曾失败
- **WHEN** 图片的视觉、Agent 语境和当前文本 embedding 均有效，但历史自动重命名阶段只有 warning
- **THEN** 系统认为该图片核心就绪，不因本次选择 `auto_name=true` 将其纳入完整重试目标

### Requirement: 完整重试必须统一应用确认后的处理选项
客户端 MUST 为一次“完整重试所有未就绪”提交一组规范化的 `reverse_image_policy` 和 `auto_name`，服务端 MUST 只将这组选项冻结到本次枚举出的核心未就绪图片的新 Job revision 或兼容活动 Job。核心已经就绪的图片不得因处理选项变化被重命名、重跑 Agent 或创建新 Job。联网策略不可用或请求选项非法时，系统 MUST 在枚举或创建任何 Job 前拒绝整次提交。

#### Scenario: 对未就绪集合启用自动重命名
- **WHEN** 用户确认 `auto_name=true` 后提交完整重试，scope 内同时存在核心就绪与未就绪图片
- **THEN** 系统仅为核心未就绪图片创建或复用带该选项的 Job
- **AND** 核心就绪图片的文件名、Job 和产物均不改变

#### Scenario: 联网策略不可用时提交完整重试
- **WHEN** 用户选择 `reverse_image_policy=auto`，但所需服务在提交边界不可用
- **THEN** 系统返回稳定错误且不为枚举集合中的任何图片创建 Job revision

### Requirement: 批量完整重试必须逐图返回可恢复结果
服务端 MUST 对枚举出的每张核心未就绪图片独立创建、复用或拒绝 Job，并返回总目标数及按结果分类的稳定摘要。单张图片发生选项冲突、提交失败或后续处理失败不得回滚或阻塞其他图片；响应 MUST 足以区分已提交、已复用、冲突和提交失败，而不得把异步阶段成功伪装为同步完成。

#### Scenario: 批量提交部分成功
- **WHEN** 枚举集合中一张图片存在活动选项冲突，其他图片可正常创建或复用 Job
- **THEN** 系统返回逐图隔离的部分成功摘要，并继续提交不冲突的图片
- **AND** 冲突图片保留既有活动 Job，不创建并行覆盖任务

#### Scenario: 当前 scope 已全部核心就绪
- **WHEN** 服务端枚举后没有核心未就绪图片
- **THEN** 系统返回目标数为零的成功结果，不创建 Job 或叶子 Task
