## Purpose

为浏览器前端提供受控的本地图片库管理能力，使用户能够浏览、预览、创建目录和重命名图片，同时阻断任意路径访问和覆盖风险。

## ADDED Requirements

### Requirement: 系统必须提供受控的图片目录和文件列表
系统 MUST 只允许访问配置的图片根目录及其子目录。列表响应 MUST 返回目录相对标识、文件名、扩展名、大小和可用于预览的媒体引用，不得返回服务器绝对路径。

#### Scenario: 列出允许目录
- **WHEN** 客户端请求一个配置图片根目录下的目录
- **THEN** 系统返回该目录中的受支持图片和子目录，并为每张图片提供媒体引用

#### Scenario: 访问根目录外路径
- **WHEN** 客户端提交包含 `..`、绝对路径或符号链接逃逸的目录标识
- **THEN** 系统返回 `400` 或 `403`，且不读取目标路径

#### Scenario: 目录不存在
- **WHEN** 客户端请求不存在的目录标识
- **THEN** 系统返回 `404`，错误标识为 `directory_not_found`

### Requirement: 系统必须安全地创建图片目录
系统 MUST 只接受单层或受控相对目录名，并 MUST 拒绝空名称、路径分隔符、控制字符和已存在的目录覆盖。

#### Scenario: 创建新目录
- **WHEN** 客户端提交合法且不存在的目录名
- **THEN** 系统创建目录并返回其稳定标识

#### Scenario: 目录名非法或已存在
- **WHEN** 客户端提交非法名称或已存在的目录名
- **THEN** 系统返回 `400` 或 `409`，且不改变现有目录

### Requirement: 系统必须安全地重命名图片
系统 MUST 在原图片所属目录内执行重命名，保留原扩展名，拒绝覆盖已有文件，并在成功后返回新的图片标识和媒体引用。

#### Scenario: 重命名成功
- **WHEN** 客户端提交存在的图片标识和合法的新文件名
- **THEN** 原文件被重命名为新文件名，扩展名保持不变

#### Scenario: 新文件名冲突
- **WHEN** 目标文件名已存在
- **THEN** 系统返回 `409`，且原文件保持不变

### Requirement: 系统必须通过媒体接口提供图片
图片预览 MUST 通过受控媒体接口读取，接口 MUST 校验图片标识属于允许的图片根目录，并 MUST 使用实际文件类型返回内容类型。

#### Scenario: 预览合法图片
- **WHEN** 客户端请求存在且受允许目录保护的图片标识
- **THEN** 系统返回图片内容及正确的媒体类型

#### Scenario: 预览非法或不存在图片
- **WHEN** 客户端请求越界或不存在的图片标识
- **THEN** 系统返回 `403` 或 `404`，不读取其他文件
