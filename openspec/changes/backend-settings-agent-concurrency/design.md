## Context

当前 `backend/config.py` 使用 `dataclass(frozen=True)` 和手工 `os.getenv` 解析配置，FastAPI lifespan 启动时只构造一次 Settings，并用它创建 SearchService、OpenCodeRunner 和任务服务。`GET /config` 只返回脱敏状态，前端没有独立的后端设置页面，也没有配置写入接口。

并行提取 change 将把 OpenCode Agent 并发数量作为启动期参数使用。该参数修改后必须避免热更新造成新旧 semaphore、运行任务和缓存模型混用，因此设置页只负责持久化待生效值，并明确要求重启。

## Goals / Non-Goals

**Goals:**

- 以 Pydantic Settings 统一承载环境变量、`.env` 和默认值，并保持现有部署兼容性。
- 提供三类后端设置展示：脱敏状态、安全可调整的 Agent 并发数量、部署环境管理的高风险参数。
- 只允许受保护接口修改并发数量；保存过程原子、可校验、可审计，并返回重启提示。
- 让任务记录能够区分有效配置与待重启配置，便于解释任务行为。

**Non-Goals:**

- 不实现通用的 `.env` 编辑器，不允许从浏览器修改密钥、路径、可执行文件或任意 URL。
- 不做运行时热更新，不迁移或取消正在运行的 Agent 任务。
- 不把前端搜索结果数量、主题、筛选器等用户偏好放入后端设置。
- 不在本 change 中改变 OpenCode 并发调度本身的 slot/worker 实现；该行为由并行提取 change 消费本设置。

## Decisions

### 1. 使用 Pydantic Settings，但保持环境优先级

引入 Pydantic Settings v2，使用字段别名映射现有变量名，并保留“显式进程环境变量优先于 `.env`、`.env` 优先于默认值”的顺序。未知环境变量默认忽略，避免部署中存在由 skill 或其他脚本读取的变量时启动失败。路径和布尔/整数值的清理规则沿用当前实现，避免无意改变部署行为。

替代方案是继续扩展手工 dataclass 解析。该方案短期改动少，但每增加一个运行参数都要重复处理类型、错误和脱敏，且难以为设置接口复用校验模型。

### 2. 并发数量是唯一可编辑的后端参数

有效值限定为 `1..8`，默认 `1`。页面只提交该字段；后端更新前先检查是否存在进程环境覆盖，存在时拒绝写 `.env`，避免产生“页面显示已保存但永远不生效”的假象。保存后返回 `settings_version`、`effective_value` 和 `restart_required`。

替代方案是允许页面实时改变内存中的 semaphore。由于 Settings 在启动期被多个服务捕获，热更新会导致任务并发、OpenCode runtime 和缓存策略的竞态，因此不采用。

### 3. `.env` 只做非敏感字段的受保护持久化

设置接口只更新 `MEMEMEOW_OPENCODE_CONCURRENCY`，使用受控路径、符号链接检查、临时文件、`fsync`、原子替换和 `0600` 权限；保留其他未知行和注释，不把完整文件内容返回给客户端。环境变量 `MEMEMEOW_SETTINGS_ADMIN_TOKEN` 只用于接口授权，不写回页面或任务记录。

替代方案是新增 JSON 覆盖文件。虽然更容易写入，但会引入新的配置优先级和运维来源；本 change 只需持久化一个非敏感字段，继续使用 `.env` 更符合现有部署模型。

### 4. 设置页是独立的运维页面

前端沿用现有单根组件的 page 切换方式，新增“后端设置”导航项和响应式设置视图。页面对只读和可编辑字段使用不同控件，显示当前有效值、待生效值、环境覆盖原因和重启提示；不把 API key 放入输入框、localStorage 或表单初始值。

### 5. 配置版本进入任务诊断而非业务结果

任务在创建和执行时记录非敏感的 `settings_version` 或并发配置摘要，任务页可展示该信息。配置更新不重写历史任务；重启后新任务使用新版本，旧终态仍保持原始诊断。

## Risks / Trade-offs

- [Risk] Pydantic Settings 的 dotenv、大小写、空字符串语义与现有解析不同。→ 保留别名和兼容测试，启动前后对同一组 `.env` fixture 做结果对比。
- [Risk] 无认证部署中开放写接口会被任意调用。→ 未配置 admin token 时禁用更新接口；启用时要求管理凭据，失败统一返回 `403`，页面自动退化为只读。
- [Risk] `.env` 写入期间被并发进程读取或被符号链接替换。→ 限制到应用 data/config 路径，拒绝符号链接，使用临时文件、fsync 和原子替换，并在写前后复核 inode/权限。
- [Risk] 用户保存后误以为立即生效。→ 接口和页面同时显示 `restart_required`、当前有效值和待生效值，任务页显示所用配置版本。
- [Risk] 并发数量被设置过高导致 provider 限流或资源耗尽。→ 固定 `1..8` 上限，默认 `1`，并由并行提取 change 的背压和 slot 互斥继续限制实际运行量。

## Migration Plan

1. 引入 Pydantic Settings，加入兼容 fixture 和 `MEMEMEOW_OPENCODE_CONCURRENCY` 默认值，保持当前 `/config` 脱敏响应兼容。
2. 增加后端设置查询接口与页面，先以只读方式验证三类字段和重启提示。
3. 启用管理凭据后开放并发字段保存，执行原子 `.env` 更新和环境覆盖拒绝逻辑。
4. 与并行提取 change 一起部署；默认仍为 `1`，验证稳定后再逐步提高并发。
5. 出现问题时删除或回退 `.env` 中的并发字段即可恢复默认单并发；旧任务记录和 sidecar 不受影响。
