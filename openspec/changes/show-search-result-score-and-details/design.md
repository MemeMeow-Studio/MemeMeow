## Context

当前 SearchRepository 已将文本查询向量与 Meme 文本 embedding 的余弦相似度作为 `(meme_id, score)` 返回并用于稳定排序，但搜索 service 只保留 `meme_id`，HTTP 层因此无法把分数投影到 `result_media`。前端搜索结果以整个正方形卡片作为复制按钮；图片库和合集已经共同复用 `ImagePreviewDialog` 读取完整图片元数据。

本变更跨越 repository 之后的 service、HTTP 投影和 Vue 搜索交互。具体行为契约见 `specs/meme-search/spec.md` 与 `specs/frontend-workbench/spec.md`。

## Goals / Non-Goals

**Goals:**

- 让 repository 已计算的相似度沿原搜索调用链无损到达对应富媒体结果。
- 保持 `results: string[]` 和现有媒体 URL 行为兼容。
- 将搜索结果详情与完整图片库详情分层，并复用既有详情组件、元数据 API 和模态焦点约束。
- 保持图片点击复制行为，同时提供语义独立的详情操作。

**Non-Goals:**

- 不新增匹配度查询 API、数据库字段、索引或缓存。
- 不在前端计算向量、不重新调用 embedding 服务，也不把相似度解释为概率或置信度。
- 不展示或下载原始 embedding 向量。
- 不改变视觉 embedding 匹配、搜索排序算法或 LLM 查询增强策略。

## Decisions

### 1. 搜索 service 返回带分数的内部排名项

Postgres 搜索 service 保留 repository 返回的 `(meme_id, score)`，在确认图片仍可访问和去重后返回轻量排名项。HTTP 层接受该内部结构，并把 `meme_id` 映射为现有受控媒体 URL，同时将有限浮点 `score` 写入对应 `result_media`。

选择沿原调用链传递，是因为分数属于当次查询和排序结果，不能脱离查询上下文按图片单独读取。备选方案“点击详情后再次查询”会增加模型调用、可能因查询增强或索引切换得到不同值，因此不采用。

### 2. 兼容主结果数组，仅扩展富媒体旁路

`results` 继续只包含去重后的 `/media/{meme_id}` URL；`result_media` 的每个条目增加 `score`。这样依赖旧主结果结构的调用方无需迁移，同时 Vue 客户端可以按稳定 `meme_id` 关联媒体与分数。

备选方案“把 `results` 改为对象数组”会破坏现有 API 契约和客户端，因此不采用。分数字段使用原始有限余弦值，前端固定为四位小数展示，不转为正确概率百分比。

### 3. 新增轻量搜索详情组件，完整详情继续复用 ImagePreviewDialog

新增专注于当次搜索上下文的对话框组件，只接收结果摘要、返回焦点和显式事件，不读取元数据。它展示余弦相似度和解释，并向父组件发出关闭或打开图片库详情事件。父组件收到后先卸载轻量对话框，再把同一结果映射成 `ImagePreviewDialog` 所需的最小 `MemeImage`，完整元数据继续由现有详情组件按 `meme_id` 加载。

备选方案“直接修改 ImagePreviewDialog 展示搜索分数”会把只在一次搜索中成立的瞬时上下文耦合进通用图片库详情；备选方案“重新实现一套完整详情”会复制元数据展示和安全处理逻辑，均不采用。

### 4. 搜索卡片拆分为容器和两个独立控件

结果项改为稳定尺寸的容器，内部图片按钮保留复制行为，容器下方提供“查看详细信息”按钮。两个按钮不嵌套，分别具有明确的可访问名称和焦点状态。对话框关闭时使用现有模态 composable 把焦点返回详情触发按钮；从轻量详情进入完整详情时，完整详情关闭后也返回该触发按钮。

## Risks / Trade-offs

- [Risk] service 返回类型变化可能影响仍假设 `list[str]` 的测试替身或适配层 → HTTP 边界在迁移期只接受明确受控的排名项，并同步更新核心调用方和契约测试；主 HTTP `results` 结构保持不变。
- [Risk] 不可访问候选过滤后分数与媒体错位 → 从同一个排名项原子投影 `meme_id`、URL 与 `score`，按 `meme_id` 去重，不依赖数组位置猜测。
- [Risk] 模态切换造成焦点丢失或两层对话框并存 → 搜索工作区只维护一个活跃详情状态，切换时先清空轻量状态再设置完整详情状态，并测试 dialog 数量和焦点恢复。
- [Trade-off] 四位小数便于比较但不提供业务阈值 → 仅说明这是相对排序参考；是否引入阈值和质量分级留给有数据校准依据的后续变更。

## Migration Plan

1. 先在开源核心扩展 service 和 HTTP 富媒体旁路，保持 `results` 兼容并通过后端契约测试。
2. 增加 Vue 类型、轻量详情组件与搜索工作区组合，执行组件、类型检查和响应式交互测试。
3. 将开源改动整理为独立 commit，按项目同步门禁等待审核；审核并进入官方 `upstream` 后，Server 再合并精确 SHA 并补充适配层字段与测试。
4. 回滚时整体回退该 commit；数据库和持久化格式均无迁移需要撤销。
