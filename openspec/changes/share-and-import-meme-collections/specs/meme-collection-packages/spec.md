## Purpose

为 MemeMeow 合集提供简单、可移植的 ZIP 表达，使使用者能够通过稳定链接下载合集的当前内容，并在同一实例或另一实例中导入该包恢复图片和成员关系。

## ADDED Requirements

### Requirement: 合集具有动态 ZIP 下载地址
系统 SHALL 为每个合集提供由合集稳定 ID 构造的 ZIP 下载地址，且 SHALL NOT 要求认证、分享 token 或预先创建导出记录。每次请求该地址时，系统 MUST 从数据库读取合集当前名称和全部当前成员，并基于本次读取结果构造新的 ZIP。

#### Scenario: 下载当前合集
- **WHEN** 使用者请求一个存在合集的 ZIP 下载地址
- **THEN** 系统返回包含该合集当前名称和当前全部成员图片的 ZIP 文件
- **AND** 响应以附件形式提供安全的下载文件名

#### Scenario: 同一链接反映后续成员变化
- **WHEN** 合集成员发生增加或移除后，使用者再次请求原下载地址
- **THEN** 新 ZIP 反映请求时数据库中的最新成员关系
- **AND** 系统不复用之前生成的 ZIP 快照

#### Scenario: 下载空合集
- **WHEN** 使用者下载一个没有成员的合集
- **THEN** 系统返回只包含有效 `manifest.json` 的 ZIP 文件

#### Scenario: 合集不存在
- **WHEN** 使用者请求不存在或不属于当前数据范围的合集下载地址
- **THEN** 系统返回资源不存在
- **AND** 不生成下载文件

### Requirement: 合集 ZIP 使用版本化可校验格式
系统 SHALL 使用 `mememeow-collection` 格式生成 ZIP。ZIP 根目录 MUST 包含一个 `manifest.json`，图片 MUST 位于 `images/` 下。manifest MUST 包含格式名称、格式版本、合集名称以及按合集成员顺序排列的成员记录；每条成员记录 MUST 包含 ZIP 内相对路径、导出时文件名、扩展名、字节数和 SHA-256。

#### Scenario: 导出有效 ZIP
- **WHEN** 系统成功导出一个非空合集
- **THEN** ZIP 中每张图片与 manifest 中一条成员记录一一对应
- **AND** 每条记录声明的字节数和 SHA-256 与实际 ZIP 文件一致

#### Scenario: 排除内部状态
- **WHEN** 系统生成合集 ZIP
- **THEN** ZIP 不包含数据范围标识、文件系统绝对路径、embedding、任务状态或分享凭据

#### Scenario: 导出期间图片不可读取
- **WHEN** 任一当前成员图片缺失、正在执行存储变更或与数据库指纹不一致
- **THEN** 系统返回稳定错误且不发送不完整 ZIP

### Requirement: 使用者可以导入合集 ZIP
系统 SHALL 接受一个符合当前支持格式版本的合集 ZIP，在完整验证包结构和 manifest 后创建新合集、导入图片并建立成员关系。导入的来源 Meme ID SHALL 只作为来源信息，系统 MUST 为新图片使用目标实例的稳定 Meme ID。

#### Scenario: 成功导入合集包
- **WHEN** 使用者上传结构、图片和校验值均有效且合集名称未被占用的 ZIP
- **THEN** 系统创建 manifest 指定名称的合集
- **AND** 将成功导入或复用的全部图片按 manifest 顺序加入该合集
- **AND** 返回来源成员到目标 Meme ID 的映射和逐项结果

#### Scenario: 合集名称冲突
- **WHEN** manifest 中的合集名称与当前数据范围已有合集重名
- **THEN** 系统返回冲突错误
- **AND** 不导入任何图片或成员关系

#### Scenario: 包结构无效
- **WHEN** ZIP 缺少 manifest、格式版本不受支持、条目与 manifest 不一致或任一声明的大小或 SHA-256 不匹配
- **THEN** 系统拒绝整个包
- **AND** 不创建合集、图片或成员关系

#### Scenario: 图片处理期间部分失败
- **WHEN** 包结构已完整通过验证，但一张或多张图片在持久化或语境任务提交期间失败
- **THEN** 系统保留已经成功导入的图片和合集成员
- **AND** 返回每张图片的成功或失败结果，不把部分成功描述为全部成功

### Requirement: 导入安全处理 ZIP 和图片
系统 MUST 在写入业务图片目录前验证 ZIP 条目和图片内容。系统 MUST 拒绝绝对路径、父目录穿越、符号链接、重复条目、超出成员数量限制或超出解压总大小限制的包，并 MUST 对每张图片应用现有支持格式、单文件大小和可解码性校验。

#### Scenario: ZIP 包含路径穿越条目
- **WHEN** 上传的 ZIP 包含绝对路径、`..` 路径或符号链接条目
- **THEN** 系统拒绝整个包
- **AND** 不向业务图片目录写入任何文件

#### Scenario: ZIP 超出资源限制
- **WHEN** ZIP 的成员数量、单张图片大小或解压后总大小超过服务端限制
- **THEN** 系统拒绝整个包并返回稳定的限制错误

#### Scenario: 图片不是有效支持格式
- **WHEN** manifest 声明的图片扩展名受支持但实际内容无法作为 PNG、JPEG 或 GIF 解码
- **THEN** 系统拒绝整个包
- **AND** 不创建合集或图片记录

### Requirement: 导入使用确定性文件冲突规则
系统 SHALL 在导入前为每张图片解析目标文件名。同名且 SHA-256 相同的现有图片 SHALL 被复用；同名但内容不同的图片 SHALL 使用原文件名 stem 与 SHA-256 前缀构造安全且不冲突的目标文件名。不同文件名的相同内容 MAY 继续作为不同 Meme 导入。

#### Scenario: 复用同名同内容图片
- **WHEN** 目标图片库存在与导入成员文件名和 SHA-256 均相同的 Meme
- **THEN** 系统复用该 Meme 并将其加入新合集
- **AND** 不创建重复图片文件

#### Scenario: 解决同名不同内容冲突
- **WHEN** 目标图片库存在同名但 SHA-256 不同的 Meme
- **THEN** 系统使用包含导入图片 SHA-256 前缀的安全文件名创建新 Meme
- **AND** 不覆盖或修改现有图片

### Requirement: 导入图片沿用现有处理生命周期
系统 SHALL 将新导入图片视为普通新图片，使用现有暂存与存储操作完成持久化，并提交常规语境处理。合集 ZIP SHALL NOT 携带或恢复 embedding；导入后 embedding SHALL 通过现有缓存生成流程重建。

#### Scenario: 导入新图片
- **WHEN** 一张包内图片在目标实例中不存在并成功写入
- **THEN** 系统为其创建新的稳定 Meme ID 并提交语境处理
- **AND** 该图片在新的 embedding generation 生效前保持现有未索引状态表达

#### Scenario: 语境任务提交失败
- **WHEN** 图片文件和 Meme 记录已经成功写入，但语境任务提交失败
- **THEN** 系统保留该图片及其合集成员关系
- **AND** 在逐项结果中报告可重试的处理失败

### Requirement: 合集界面提供下载和导入操作
系统 SHALL 在合集工作区提供下载 ZIP、复制下载链接和导入合集 ZIP 的操作，并 SHALL 为导入校验、名称冲突、逐项部分失败和成功结果提供文字反馈。

#### Scenario: 复制动态下载链接
- **WHEN** 使用者在合集详情选择复制下载链接
- **THEN** 界面复制该合集稳定的 ZIP 下载地址
- **AND** 不调用创建分享记录的接口

#### Scenario: 从合集工作区导入 ZIP
- **WHEN** 使用者选择一个 ZIP 并提交导入
- **THEN** 界面显示导入进行状态和最终逐项结果
- **AND** 成功后可以直接打开新建合集
