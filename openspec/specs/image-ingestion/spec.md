## Purpose

为用户提供批量导入表情图片的行为契约，统一处理格式校验、文件名安全、重复文件、基于 Agent 语境标题的可选自动命名，并允许批量操作部分成功。
## Requirements
### Requirement: 系统必须校验上传图片
系统 MUST 支持 PNG、JPG、JPEG 和 GIF 图片，并 MUST 校验文件内容确实是可读取的图片。系统 MUST 拒绝不支持的扩展名、伪造内容和超出配置大小限制的文件。合法图片保存成功时，系统 MUST 在当前 scope 中同时建立不可变 `meme_id`、文件指纹和 `pending` 语境记录，并在响应中返回稳定 Meme 标识；文件或数据库任一侧失败时不得报告上传成功。

#### Scenario: 上传合法图片
- **WHEN** 客户端上传一个受支持且可解码的图片到允许目录
- **THEN** 系统保存图片，在当前 scope 创建对应 Meme 和初始语境，并返回 `meme_id`、原始文件名和保存结果

#### Scenario: 提交已废弃的目标目录
- **WHEN** 客户端上传图片时提交 `directory` 或其他目标目录字段
- **THEN** 系统返回参数错误
- **AND** 不保存该请求中的图片

#### Scenario: 上传非法文件
- **WHEN** 客户端上传不支持格式、损坏或超限文件
- **THEN** 系统拒绝该文件并返回可识别的校验错误，不产生目标文件或 Meme 记录

#### Scenario: 数据库提交失败
- **WHEN** 图片文件已完成暂存但 Meme 记录无法提交
- **THEN** 系统返回失败并清理或隔离未被数据库引用的文件，不让其出现在图片库中

### Requirement: 系统不得因批量中的单个文件失败而回滚其他成功文件
批量上传 MUST 为每个文件返回独立结果。保存成功的文件 MUST 保留；失败文件 MUST 返回错误原因，且不得覆盖当前数据范围图片根中的已有文件。

#### Scenario: 批量上传部分失败
- **WHEN** 一次上传中部分文件合法、部分文件重复或非法
- **THEN** 系统返回逐文件成功或失败结果
- **AND** 成功文件可立即在扁平图片库中看到

### Requirement: 自动命名必须是显式可选行为
客户端未启用自动命名时，系统 MUST 使用清理后的原始文件名；启用自动命名时，系统 MUST 在 Agent 语境成功写入非空 `title` 后异步派生不含路径结构的候选文件名并提交重命名；若标题缺失、候选文件名非法、目标冲突或目标指纹变化，系统 MUST 保留当前文件名并将自动重命名阶段记录为可恢复 warning，不得生成空文件名、路径或内部保留名称。

#### Scenario: 自动命名成功
- **WHEN** 客户端启用自动命名且 Agent 语境写入有效非空标题
- **THEN** 系统使用清理后的标题在当前数据范围图片根中生成文件名
- **AND** 保留原图片扩展名

#### Scenario: 自动命名失败
- **WHEN** 客户端启用自动命名但 Agent 语境没有有效标题，或重命名目标非法、冲突或已变化
- **THEN** 系统保留当前清理后的文件名，并以可恢复 warning 标记自动重命名未完成
- **AND** 后续文本 embedding 阶段仍可按处理链继续

### Requirement: 图片入库后必须异步启动图片处理链
系统 MUST 在图片字节和 Meme 记录成功提交后，为当前图片 SHA-256 创建或复用从视觉向量阶段开始的图片处理任务，并在上传结果中返回可轮询的处理任务标识。上传请求 MUST NOT 等待视觉模型或 Agent 语境执行，也 MUST NOT 在视觉向量成功前直接启动该图片的 Agent 语境任务。

#### Scenario: 单张图片成功入库
- **WHEN** 客户端上传一张合法且未重复的图片
- **THEN** 系统创建或复用从视觉向量阶段开始的处理任务、返回可轮询的任务标识，并让图片立即出现在图片库中

#### Scenario: 批量图片成功入库
- **WHEN** 一次上传中的多张图片分别成功保存
- **THEN** 系统为每张成功图片分别创建或复用处理任务，且不同图片的视觉、Agent 和文本阶段允许并发和跨阶段交错

#### Scenario: 视觉服务不可用
- **WHEN** 图片已经成功入库但视觉向量任务因配置缺失或服务不可用而失败
- **THEN** 系统保留图片及失败诊断，不回滚其他成功图片，也不为该图片自动提交 Agent 语境任务
